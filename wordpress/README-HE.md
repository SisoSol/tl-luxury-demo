# T&L — מערכת הניהול ונספח בדיקות למתכנת

## לבעלי החנות: כתובת אחת, מערכת אחת

ניהול החנות נעשה **בהתקנת WordPress אחת עם WooCommerce בתוכה**. לבעלים נמסרת כתובת כניסה אחת; לכל מנהל משתמש אישי, ושני המשתמשים עובדים באותה חנות. WooCommerce אינו אתר ניהול נוסף.

לפני הקמת האחסון, הכניסה דרך /admin מציגה הסבר בלבד. אחרי ההקמה והגדרת הכתובת, היא מפנה ללוח **T&L — החנות** של ההתקנה הקבועה. אין כאן המלצה לערוך מוצרים בדפדפן מקומי או לנהל שתי גרסאות של הקטלוג. אתר התצוגה הסטטי אינו מסתנכרן אוטומטית עם החנות.

**מדריכי המסירה:** production/MANAGEMENT-HE.html לבעלים ו־wordpress/README-PRODUCTION-HE.md להקמה ולהדרכה. בקרות ההשקה המפורטות מתועדות ב־wordpress/tl-luxury-tools/README-PRODUCTION-HE.md.

## נספח טכני — סביבות בדיקה בלבד

הסעיפים מכאן מיועדים למתכנת. הם אינם מציעים כתובת ניהול חלופית לבעלי החנות.

### מה נבדק בסביבת הדפדפן

WordPress Playground מאפשר להריץ WordPress ו־WooCommerce בסביבת בדיקה מבודדת. כך נבדקו עריכת מוצרים ומדיה, קופונים, תפקידי משתמש ובקרות פתיחת המכירה. הוא אינו אחסון משותף לחנות העסקית. כל סביבת דפדפן היא סביבת בדיקה, ולא המקום לניהול הזמנות אמת או גיבוי העסק. [תיעוד Playground](https://developer.wordpress.org/playground/handbook/web-instance/)

blueprint.json מיועד לתרחיש בדיקה עם קטלוג וחשבונות בדיקה; blueprint-clean-install.json מיועד לאימות ההתקנה הנקייה. אין לייבא אותם לשרת החי במקום הליך התקנה מוסדר.

### זריעת נתוני בדיקה

זריעת הקטלוג זמינה רק כש־TL_LUXURY_DEMO מוגדר במפורש. בהתקנת הפרודקשן אין להפעיל את הקבוע, ליצור משתמשי ניסוי או להעתיק סיסמאות מסביבת בדיקה. התקנת התבנית ותוסף הניהול הרגילה אינה זורעת מוצרים או מנהלי חנות.

### ההבדל בין התצוגה לחנות הקבועה

GitHub Pages מציג קבצים סטטיים; הוא אינו מריץ WordPress, PHP או מסד נתונים. קוד מסכי עריכה מקומיים ששימש בגרסאות קודמות הוא היסטוריית פיתוח, לא כלי תפעול לבעלים. המימוש הקבוע של עריכת מוצרים, תמונות, הזמנות ותוכן הוא ב־WordPress עם WooCommerce בלבד. [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

### בדיקות לפני מסירה

מתקינים בעותק בדיקות, בודקים את התבנית והתוסף מול הגרסאות שנבחרו ואת הרשאות שני המנהלים; מאמתים שמירה על השרת דרך שני חשבונות ולא רק דרך דפדפן יחיד. בודקים את כתובת הכניסה הציבורית במצב לא מוגדר ובמצב מוגדר, ושאין ממנה עורך מקומי או קישור תפעולי לסביבת בדיקה.

בדיקות חיבור PayPlus, דואר, משלוחים וחשבוניות נעשות עם החשבונות העסקיים המתאימים. תוצאת בדיקה בסביבת דפדפן אינה אישור שהשירותים האלו מחוברים לחנות העסקית. תנאי הפתיחה והגבלות מסלול האיסוף מתועדים במדריך הפרודקשן, בלי לעקוף בקרות באתר החי.
